# PlanZy

Ассистент преподавателя и тренера: веб-кабинет для ведения учеников,
расписания, уроков и оплат — плюс Telegram-бот как быстрый помощник
и автоматические напоминания в WhatsApp.

## Что делает

**Главный интерфейс — веб-кабинет.** В нём тренер ведёт учеников, расписание,
уроки, оплаты и настройки. Бот — вспомогательный канал: быстрая диктовка
итога урока и напоминания.

1. В веб-кабинете (`/admin`) вы ведёте учеников, регулярное расписание
   (слоты «по вторникам в 17:30»), разовые переносы и отмены, уроки и оплаты.
2. Итог урока можно надиктовать голосом через Wispr Flow прямо в Telegram-бот.
3. Gemini Flash разбирает текст в строгий JSON (тема, ДЗ, оценка, оплата, приватные заметки).
4. Система списывает занятие с баланса и сохраняет историю в те же таблицы,
   что и кабинет, — данные всегда синхронны.
5. Бот выдаёт кнопку `wa.me` с готовым отчётом родителю и ссылку на веб-карточку урока.
6. По правилам напоминаний приходят сводки: вечером — о занятиях на завтра,
   утром — о занятиях на сегодня, плюс предупреждение о низком балансе.

## Быстрый старт

### 1. Клонирование и окружение

```bash
git clone <repo-url> planzy
cd planzy
python -m venv .venv
```

Активация виртуального окружения:

- Windows: `.venv\Scripts\activate`
- Linux/macOS: `source .venv/bin/activate`

### 2. Установка зависимостей

```bash
pip install -e ".[dev]"
```

### 3. Настройка окружения

```bash
copy .env.example .env    # Windows
cp .env.example .env      # Linux/macOS
```

Заполните в `.env`:

- `TELEGRAM_BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
- `OWNER_TELEGRAM_ID` — ваш Telegram user_id (узнать у [@userinfobot](https://t.me/userinfobot))
- `GEMINI_API_KEY` — ключ из [Google AI Studio](https://aistudio.google.com/app/apikey)
- `BASE_URL` — публичный домен (например, `https://planzy.dvorzhik.site`)

> **Настройки тренера живут в БД, а не в `.env`.** Цена занятия, валюта,
> часовой пояс и порог низкого баланса хранятся отдельно для каждого тренера
> и меняются в кабинете (`/admin/settings`). Переменные `LESSON_PRICE`,
> `CURRENCY`, `TIMEZONE` в `.env` — только запасные значения по умолчанию.

### 4. Инициализация базы данных

```bash
# Применить миграции
alembic upgrade head

# Создать тенанта-владельца
python -m scripts.seed

# Или создать тенанта вместе с демо-данными
python -m scripts.seed --demo
```

### 5. Запуск

```bash
python -m app.main
```

Приложение поднимет FastAPI, Telegram-бот и планировщик в одном процессе.
Хост и порт берутся из `.env` (`WEB_HOST`, `WEB_PORT`, по умолчанию `127.0.0.1:8000`).
Если порт занят (в Windows это часто `WinError 10013`), поменяйте `WEB_PORT`
и `BASE_URL` в `.env` — например, на `8010`.

### 6. Проверка работоспособности

```bash
# Сквозной smoke-тест: БД → Repository → Services → веб-роуты
python -m scripts.smoke_test
```

Ожидаемый результат — строка `ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ`.

### 7. Веб-кабинет (главный интерфейс)

Кабинет доступен по адресу `{BASE_URL}/admin`. Вход — по ссылке с токеном,
которую выдаёт команда `/admin` в боте (или `python -m scripts.seed` при первом
запуске). Токен хранится в cookie-сессии.

Разделы кабинета:

| Раздел | Что делает |
|---|---|
| Дашборд | сводка: ученики, занятия на сегодня, должники |
| Ученики | карточки учеников и групп, баланс, контакты, публичные ссылки |
| Расписание | регулярные слоты, разовые переносы/отмены/доп. занятия, конфликты |
| Уроки | журнал уроков, ручное создание и редактирование |
| Напоминания | правила рассылки (за день, утром, при низком балансе) |
| Настройки | цена занятия, валюта, часовой пояс, порог низкого баланса |

Подробная инструкция для тренера — в [`docs/admin-guide.md`](docs/admin-guide.md).

### 8. Проверка Telegram-бота (вспомогательный канал)

1. Откройте бота в Telegram и отправьте `/start` — **это обязательный первый шаг**:
   Telegram запрещает боту писать первым, поэтому до `/start` рассылка
   будет падать с ошибкой `Bad Request: chat not found`.
2. Проверьте команды: `/help`, `/admin`, `/balance`, `/today`, `/dossier`.
3. Отправьте обычным текстом диктовку об уроке, например:
   `Миша, разбирали вилки, домашка задачи 12-15, оценка 4, оплатил 400 за 8 занятий`.
   Бот должен вернуть карточку урока со ссылкой WhatsApp и ссылкой на веб-страницу урока.

> **Важно:** `OWNER_TELEGRAM_ID` в `.env` должен совпадать с вашим Telegram ID —
> иначе `WhitelistMiddleware` молча проигнорирует сообщения.

### 8. Локальный `BASE_URL` и кнопки-ссылки

Telegram принимает в inline-кнопках **только абсолютные публичные HTTP(S)-адреса**.
Если `BASE_URL` указывает на локальный адрес (`http://localhost:8010`,
`http://127.0.0.1:8010`), Telegram отвечает
`Bad Request: inline keyboard button URL ... is invalid: Wrong HTTP URL`
и **отклоняет всё сообщение целиком**.

PlanZy обрабатывает это мягко: [`app/bot/keyboards.py`](app/bot/keyboards.py)
проверяет URL через `is_public_url()` и просто **не добавляет** невалидные кнопки,
а бот дописывает в отчёт предупреждение:

> ℹ️ Ссылки на карточку и досье скрыты: `BASE_URL` указывает на локальный адрес.

То есть диктовка и `/dossier` работают всегда, но кнопки «Карточка» и «Досье»
появятся только с публичным адресом. Чтобы получить их локально, поднимите туннель:

```bash
# вариант 1: cloudflared (без регистрации)
cloudflared tunnel --url http://127.0.0.1:8010

# вариант 2: ngrok
ngrok http 8010
```

Сервис выдаст адрес вида `https://random-words.trycloudflare.com` — пропишите его
в `.env` как `BASE_URL` и перезапустите приложение. Кнопки заработают.

## Архитектурные решения

### Сайт главный, бот — помощник

Основной интерфейс — веб-кабинет: в нём тренер ведёт учеников, расписание,
уроки и оплаты. Telegram-бот остаётся быстрым вспомогательным каналом:
диктовка итога урока голосом и напоминания. Оба интерфейса работают с одними
и теми же таблицами через общий Service Layer, поэтому данные всегда синхронны.
Подробности — в [`docs/architecture-web-first.md`](docs/architecture-web-first.md).

### Расписание: слоты + разовые отклонения

Регулярное расписание хранится в таблице `ScheduleSlot` («по вторникам в 17:30
у Ани») — это единственный источник правды. Разовые изменения (отмена, перенос,
дополнительное занятие) хранятся в `ScheduleException` на конкретную дату.
[`ScheduleService.get_day_schedule()`](app/services/schedule_service.py:574)
собирает расписание на день, накладывая отклонения на слоты.

### Напоминания по правилам

Рассылка управляется таблицей `ReminderRule` с тремя типами:

- `day_before` — вечером о занятиях на завтра;
- `morning_of` — утром о занятиях на сегодня;
- `low_balance` — предупреждение о низком балансе.

Каждое правило можно включить/выключить и задать время. Защита от дублей —
двухуровневая: in-process guard в планировщике и журнал `DispatchLog` в БД
(уникальность по `tenant_id + entity_id + rule_kind + dispatch_date`).

### Мультитенантность с первого дня

Все таблицы данных содержат `tenant_id`. Это обеспечивает логическую
изоляцию данных разных тренеров и позволяет перейти к SaaS без
болезненной миграции схемы.

### Repository-слой

Весь SQL сосредоточен в [`app/db/repository.py`](app/db/repository.py).
Каждый метод принимает `tenant_id` — изоляция данных гарантируется
на уровне доступа к БД, а не только в бизнес-логике.

### SQLite с WAL

Включены PRAGMA `journal_mode=WAL`, `busy_timeout=5000`, `foreign_keys=ON`.
WAL позволяет читателям работать параллельно с писателем — критично,
когда бот записывает урок, а родитель открывает публичную страницу.

### Переход на PostgreSQL

Код написан на SQLAlchemy ORM, поэтому переход сводится к смене
`DATABASE_URL` и применению миграций. Планируется при появлении
второго платящего тренера.

## Страницы

### Кабинет тренера (по токену)

- `/admin` — дашборд: ученики, занятия на сегодня, должники.
- `/admin/students` — список учеников и групп, карточки, баланс.
- `/admin/schedule` — регулярное расписание, переносы, отмены, конфликты.
- `/admin/lessons` — журнал уроков, ручное редактирование.
- `/admin/reminders` — правила напоминаний.
- `/admin/settings` — цена, валюта, часовой пояс, порог низкого баланса.

### Публичные страницы (по токену, без авторизации)

- `/l/{token}` — смарт-карточка для родителя: расписание, последнее занятие,
  ДЗ, примечание и итоги. Истории занятий и оплаты на карточке нет.
  Приватные заметки (`internal_notes`) никогда не публикуются.
- `/lesson/{token}` — страница одного занятия: ДЗ, план, оценка (для родителя или чата).
- `/dossier/{token}` — досье ученика для преподавателя: история тем, динамика оценок, план.
- `/health` — проверка работоспособности сервиса.


## Иконка сайта (favicon)

Иконка — шахматный конь ♞ на фирменном синем фоне `#3b6fe0`
(совпадает с цветом `brand-500` из Tailwind-конфига шаблонов).

Артефакты лежат в `app/web/static/`:

| Файл | Назначение |
|---|---|
| `favicon.svg` | вектор, основной для современных браузеров |
| `favicon.ico` | 16/32/48, legacy и запросы `/favicon.ico` |
| `favicon-32.png` | растровая иконка 32×32 |
| `favicon-192.png` | Android / PWA, 192×192 |
| `apple-touch-icon.png` | iOS «на домашний экран», 180×180 |

Подключение — в обоих корневых шаблонах (`base.html` и `admin/base.html`).

Пересобрать после правки силуэта:

```bash
python -m scripts.make_favicons
```

Скрипт не требует зависимостей (только `zlib` и `struct`), рисует силуэт
из символьной матрицы и сохраняет PNG/ICO. Готовые файлы коммитятся
в репозиторий, поэтому на сервере запускать его не нужно.

## Деплой

Подробная пошаговая инструкция — в [`deploy/README.md`](deploy/README.md).

Готовые артефакты:

| Файл | Назначение |
|---|---|
| [`deploy/planzy.service`](deploy/planzy.service) | systemd-юнит (автозапуск, рестарт, graceful shutdown) |
| [`deploy/nginx-planzy.conf`](deploy/nginx-planzy.conf) | reverse proxy + SSL + отдача статики |
| [`deploy/backup.sh`](deploy/backup.sh) | ежедневный бэкап SQLite с проверкой целостности |
| [`deploy/deploy.sh`](deploy/deploy.sh) | обновление кода на сервере одной командой |

Кратко:

```bash
# На сервере, от пользователя planzy
cd /opt/planzy/app
git clone git@github.com:dvorzhik/PlanZy.git .
python3.12 -m venv .venv && .venv/bin/pip install -e .
cp .env.example .env && nano .env      # заполнить токены, APP_ENV=production
.venv/bin/alembic upgrade head
.venv/bin/python -m scripts.seed

# Системная часть (от root)
sudo cp deploy/planzy.service /etc/systemd/system/
sudo systemctl enable --now planzy
sudo cp deploy/nginx-planzy.conf /etc/nginx/sites-available/planzy
sudo ln -sf /etc/nginx/sites-available/planzy /etc/nginx/sites-enabled/planzy
sudo certbot --nginx -d planzy.duckdns.org
```
